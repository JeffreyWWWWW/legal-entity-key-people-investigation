# Skill 版本可追溯性设计

## 背景

当前 Plugin 已在 `plugins/legal-entity-key-people-investigation/.codex-plugin/plugin.json` 中维护 Plugin 版本，但调查状态和交付物没有记录该版本。用户需要在首次响应、正式 JSON 和 Excel 审阅件中明确知道本次使用的 Skill 版本，并确保版本随 Plugin 发布更新自动同步。

本次功能以当前 Plugin 版本 `1.0.1` 为基线，不因新增记录功能而修改版本号。后续发布时，版本号按现有语义化版本流程递增，所有新调查和报告自动读取新版本。

## 目标与非目标

### 目标

- Skill 首次响应顶部显示 `Skill 版本：<version>`。
- 调查状态 JSON 顶层增加标准字段 `skill_version`。
- 正式 JSON 保留并交付 `skill_version`。
- Excel“任务概览”显示 `Skill 版本`及对应版本值。
- Plugin 版本只有一个来源，初始化和渲染过程不分别硬编码版本。
- 旧状态缺少版本字段时，在校验阶段明确报错。

### 非目标

- 不新增独立的 Skill 发布系统或运行时更新检查。
- 不改变现有 `规范版本` 和 `渲染器版本` 的含义。
- 不修改正式交付文件名规则。
- 不自动修改已有旧状态文件或历史交付物。

## 版本来源与数据流

`plugin.json` 的顶层 `version` 是唯一事实来源，当前值为 `1.0.1`。需要版本的脚本通过稳定的仓库相对路径读取该文件，并校验其为三段式语义化版本字符串。读取失败或格式不正确时应终止初始化或渲染并给出明确错误，不生成缺少版本的状态或报告。

数据流如下：

1. Skill 被触发，首次响应模板读取/采用 Plugin 版本并在顶部输出版本提示。
2. `init_state.py` 读取 Plugin 版本，将其写入状态顶层 `skill_version`。
3. JSON Schema 将 `skill_version` 声明为必填字符串，并限制为三段式版本号。
4. 校验器拒绝缺少或格式错误的 `skill_version`。
5. Excel 渲染器从已校验状态读取 `skill_version`，在“任务概览”增加 `Skill 版本`行。
6. 正式 JSON 由同一状态复制/交付，因此自然包含该字段。

## 状态结构变更

状态顶层新增：

```json
"skill_version": "1.0.1"
```

该字段与现有 `规范版本` 并列。`规范版本`继续表示调查状态 Schema/事实结构版本；`skill_version`表示生成本次调查流程所使用的 Plugin Skill 版本；`渲染元数据.渲染器版本`继续表示 Excel 渲染脚本版本。三者语义独立，均保留在状态中。

## 对话行为

首次响应（即 Skill 接管调查请求后的第一条正式回复）顶部固定显示一行：

```text
Skill 版本：1.0.1
```

后续同一调查任务的回复不重复播报，除非用户明确询问版本，或开启了新的调查任务。版本提示不改变启动门槛：缺少主体或技术主题时仍只收集缺失信息，不开始外部调查。

## Excel 展示

在现有“01-任务概览”工作表中增加一行：

```text
Skill 版本 | 1.0.1
```

该行使用与 `规范版本`、`渲染器版本`相同的概览样式，位于版本相关信息区域；不在其他明细表重复添加，避免噪声。

## 兼容与错误处理

- 新初始化状态始终写入 `skill_version`。
- 旧状态若没有 `skill_version`，Schema 校验失败并提示需要补齐或重新初始化；渲染器不会绕过校验继续生成 Excel。
- 若 `plugin.json` 不可读、版本为空或不是 `X.Y.Z` 格式，初始化和渲染应返回非零退出码并说明版本来源问题。
- 现有状态哈希逻辑继续排除整个 `渲染元数据`，但会包含 `skill_version`；版本变更会使事实状态哈希变化，从而清楚标记报告所基于的 Skill 版本。

## 测试策略

- Schema 测试：包含合法 `skill_version` 的状态通过；缺失、空值、非字符串和非语义化版本失败。
- 初始化测试：生成状态中的 `skill_version` 等于 `plugin.json.version`；修改版本源后重新初始化能得到新值。
- 渲染测试：概览行包含 `Skill 版本`及状态中的值；渲染器不使用独立硬编码值。
- 回归测试：现有状态校验、交付路径和工作簿渲染测试继续通过。
- 对话文案检查：Skill 文档明确首次响应顶部版本播报规则。

## 验收标准

使用当前仓库版本 `1.0.1` 新建一次调查状态并渲染 Excel 时：

1. 首次响应顶部出现 `Skill 版本：1.0.1`。
2. 状态及正式 JSON 顶层存在 `"skill_version": "1.0.1"`。
3. Excel“01-任务概览”显示 `Skill 版本`和 `1.0.1`。
4. 将 `plugin.json.version` 更新到下一发布版本后，新生成状态和报告自动显示该新版本，无需再改脚本中的版本常量。
5. 缺少 `skill_version` 的旧状态无法通过校验，也不会生成报告。
