# 法律主体核心人员调查 v1.2.0 质量门槛设计

日期：2026-08-31  
状态：待用户审阅  
目标版本：Plugin 1.2.0、状态规范 1.1.0、渲染器 1.1.0

## 1. 背景与目标

现有 1.1.0 已建立公司主体、主体关系、核心人员、人员身份、证据、查询和缺口之间的可追溯结构，但实际交付暴露出四类质量缺口：

1. 查询记录可以用泛化数据源名称和模板化查询词标记为独立核验，无法复现实际访问过程。
2. 找到 CEO 后仍可能遗漏登记负责人、控制人、创始人及技术研发负责人，工作簿没有直接展示角色覆盖率。
3. 母公司或集团人员可能直接挂到目标子公司，既有文档禁止该行为，但校验器未验证关系路径和证据直接记载主体。
4. 来源类型是自由文本，行业媒体可能被包装成官方任命新闻并获得过高证据等级。

本次修订的目标是将可以确定性判断的要求下沉到 Schema 和业务校验器，将调查判断规则保留在 Skill 文档，并通过 Excel 覆盖矩阵使缺口可见。生成的审阅件必须区分“结构完整”“调查完成”和“事实已核验”，不得用记录数量替代调查质量。

## 2. 范围

### 2.1 包含

- 升级调查状态 Schema，增强查询、证据、人员身份和调查结果的表达能力。
- 新增 v1.0.0 到 v1.1.0 的显式迁移脚本。
- 加强跨对象业务校验和调查完成门槛。
- 调整调查工作流与证据规则，使文档与确定性校验一致。
- 改造 Excel 审阅件并新增角色覆盖矩阵。
- 为 Schema、校验器、迁移器、渲染器和完整交付流程增加自动化测试。
- 通过行为场景验证更新后的 Skill 能生成符合新约束的状态。

### 2.2 不包含

- 不修改任何已有 Excel、JSON 或用户输入文件。
- 不原地升级 `working/` 或 `outputs/` 中的历史状态；迁移只写入用户指定的新路径。
- 不重新调查品牌权属、SKU 制造商、专利、发明人或 FTO。
- 不要求公开信息一定能找到某类人员；“合理未发现”“访问受限”“付费墙”仍是合法结论。
- 不把统计评分作为是否通过校验的唯一依据。
- 不在本版本引入网络爬虫、浏览器自动化或付费数据库集成。

## 3. 设计原则

1. **事实与过程分离**：证据记录描述来源能证明的事实；查询记录描述调查人员实际做过的访问。
2. **直接主体优先**：人员身份归属于来源直接记载的法律主体；跨主体纳入通过关系路径表达，而不是改写所属主体。
3. **角色维度完备**：每个必查维度都必须有独立调查结论，但结论可以是已发现、合理未发现或受限。
4. **来源等级有上限**：来源类别决定可授予的最高证据等级，人工命名不能抬高等级。
5. **机械规则自动执行**：可通过字段、引用和枚举判断的约束进入 Schema 或校验器，不依赖模型记忆。
6. **历史文件只读**：新规范通过复制迁移，不覆盖历史底稿和审阅件。

## 4. 状态模型 1.1.0

### 4.1 查询记录

保留现有字段并新增：

| 字段 | 类型 | 要求 |
|---|---|---|
| `数据源类型` | 枚举 | `企业登记`、`监管文件`、`公司官网`、`官方公告`、`官方产品文件`、`新闻媒体`、`行业媒体`、`第三方数据库`、`搜索服务`、`用户材料`、`其他` |
| `实际访问位置` | 非空字符串或 null | 独立核验必须为具体 URL、登记入口或文件路径 |
| `访问内容摘要` | 字符串 | 成功访问必须说明看到的内容或检索结果 |
| `未命中范围` | 字符串 | `已查询但未发现`时必填，描述已检查的页面、登记范围或角色范围 |
| `候选URL` | 唯一字符串数组 | 搜索服务返回的候选位置，不等同于原始来源 |

`数据源`保留为用户可读名称，例如“SEC EDGAR”或“Camco About”，不得作为来源分类使用。

规则：

- `是否独立核验=true`时，`数据源类型`不得为`搜索服务`或`用户材料`，且`实际访问位置`和`访问内容摘要`必须非空。
- `访问结果=成功`时必须填写`访问内容摘要`。
- `命中情况=已查询但未发现`时必须填写`未命中范围`，且不得引用命中证据。
- `命中情况=已发现`时必须引用至少一条证据。
- `搜索服务`查询只能保存候选 URL；访问候选原始页面后必须新建一条查询记录。
- 单条查询只有一个`查询维度`，不得以同一查询记录同时代表多个角色维度。

### 4.2 证据记录

将自由文本来源拆成：

| 字段 | 类型 | 说明 |
|---|---|---|
| `来源类别` | 与查询的数据源类型共用枚举 | 用于确定等级上限 |
| `发布主体` | 非空字符串 | 实际发布或登记该内容的机构/公司 |
| `标题` | 非空字符串 | 原始标题 |
| `原始URL或文件路径` | 非空字符串 | 替代原`URL或文件路径` |
| `关键原文` | 非空字符串 | 支撑结论的原始内容 |

证据等级上限：

| 来源类别 | 最高等级 |
|---|---|
| 企业登记、监管文件 | 强证据 |
| 公司官网、官方公告、官方产品文件 | 较强证据 |
| 新闻媒体、行业媒体、第三方数据库 | 线索证据 |
| 搜索服务、用户材料 | 不得创建独立核验证据，只能留在线索查询或输入材料中 |
| 其他 | 默认线索证据，除非未来规范显式增加类别 |

证据仍必须保存查询日期、文件日期、证明范围、关联对象、核验状态和持续有效说明。来源类别只限定上限，不自动保证证据充分。

### 4.3 人员身份

新增：

| 字段 | 类型 | 说明 |
|---|---|---|
| `证据直接记载主体引用` | `ENT-*` | 来源直接把该人员与哪个主体关联 |
| `关联路径引用` | `REL-*`数组 | 将该人员纳入目标业务调查时依赖的已核验关系路径 |
| `是否直接任职证据` | boolean | 证据是否直接记载其在所属主体任职 |

约束：

- `所属主体引用`必须等于`证据直接记载主体引用`。
- 若人员所属主体不是目标主体，`主体层级`不得为`目标主体`，且必须提供从目标主体到所属主体的连续已核验关系路径。
- 关系路径的每条关系必须有非线索证据，且最终到达人员所属主体。
- 不得把组织、基金或公司写入`核心人员`；人员规范姓名必须指向自然人。
- 同一自然人的历史身份和当前身份分开建档，不以旧资料升级当前身份。

### 4.4 角色覆盖结论

在每个`主体调查结果`中新增`角色覆盖`数组。每个对象包含：

- `查询维度`
- `结论`：`已发现`、`合理未发现`、`访问受限`、`付费墙`、`不适用`、`待调查`
- `查询记录引用`
- `人员身份引用`
- `不适用理由`
- `复核建议`

目标主体默认必查维度：

1. 主体身份
2. 主体关系
3. 登记负责人
4. 控制与所有权
5. 创始人与最高管理层
6. 技术与研发负责人

当证据表明目标产品由独立业务线承载时，增加`目标业务负责人`。`不适用`仅允许用于创始人或目标业务负责人，且必须填写理由；其他必查维度不得用`不适用`绕过调查。

原`最高管理层`查询维度拆成`创始人与最高管理层`，避免只找到 CEO 后忽略创始人。原有状态迁移时保持旧查询事实，并把新增维度标为`待调查`，不自动推断完成。

## 5. 业务校验器

### 5.1 查询真实性校验

新增 `_validate_query_traceability`：

- 验证独立核验所需的具体访问位置、摘要和来源类型。
- 拒绝已知泛化占位语，例如“原始官网、监管文件或公开登记入口”。实现采用有限、明确的占位值集合，不使用模糊自然语言评分。
- 拒绝搜索服务或用户材料标记为独立核验。
- 验证未命中范围和命中证据引用互斥。
- 验证候选 URL 与证据原始 URL 的职责分离。

同一时间戳或相似查询词本身不构成失败，因为批量调查可能合法发生；它们作为审阅警示统计展示，不作为确定性硬门槛。

### 5.2 来源等级校验

新增 `_validate_evidence_source_ceiling`：

- 按`来源类别`检查`证据等级`不超过上限。
- 搜索服务和用户材料不得作为已核验事实证据。
- 已核验证据必须有发布主体、原始位置、关键原文和至少一个关联对象。

### 5.3 主体路径校验

扩展 `_validate_position_evidence`：

- 验证所属主体与证据直接记载主体相同。
- 验证非目标主体身份有连续、已核验、与目标业务相关的关系路径。
- 验证路径起于对应调查结果的目标主体，止于人员所属主体。
- 拒绝把母公司人员作为子公司直接身份写入。

### 5.4 覆盖与完成门槛

新增 `_validate_role_coverage` 并改造 `_validate_query_results`：

- 每个目标主体必须恰有一组必查角色覆盖结论。
- `已发现`必须有成功独立核验查询和已核验或部分核验身份/主体事实。
- `合理未发现`必须有成功独立核验查询、具体未命中范围，且不得存在未处理的相反线索。
- `访问受限`和`付费墙`必须有对应访问结果，并使主体事实状态最多为`待核验`或`部分核验`。
- 任一必查维度为`待调查`时，主体不得标记`调查完成`。
- 找到 CEO 不会自动满足登记负责人、控制与所有权或技术研发负责人维度。

调查完成表示必要维度均形成可审计结论，不表示所有人员都已找到。事实核验状态继续表达结论强度。

### 5.5 自然人校验

确定性校验只拦截明确的组织实体：

- `核心人员`新增必填字段`对象类型`，取值为`自然人`或`自然人待复核`。
- 迁移时所有既有核心人员标为`自然人待复核`，只有重新校验或明确输入后升级。
- 已知机构名称不使用持续扩大的黑名单推断；当名称无法确定时建立冲突项，而不是自动拒绝。

组织不得保存在核心人员集合中。`自然人待复核`只表达对象性质尚未完成核验，不得用于已核验人员身份；人员身份标记为已核验前，对象类型必须升级为`自然人`。

## 6. 迁移策略

新增 `scripts/migrate_state.py INPUT OUTPUT`：

1. 只接受规范版本 1.0.0，输出规范版本 1.1.0。
2. `INPUT`和`OUTPUT`解析后必须为不同路径；输出存在时默认失败，显式`--force`才可覆盖输出。
3. 复制所有既有事实和稳定编号。
4. 旧证据的`来源类型`映射到新`来源类别`时采用保守规则；无法确定时设为`其他`并降为线索证据或待核验。
5. 旧查询没有具体访问位置或摘要时，不保留`是否独立核验=true`；改为 false，并建立迁移缺口。
6. 新增角色覆盖全部从既有引用计算；无法满足新门槛的维度标为`待调查`。
7. 不根据旧叙述文本创造新人员、关系或证据。
8. 重算阶段判断和状态哈希，记录迁移来源与时间。

迁移脚本的目的，是安全表达“旧数据在新规范下还缺什么”，不是让旧状态自动通过新门槛。

## 7. Excel 审阅件 1.1.0

保留现有五张工作表，新增`06-覆盖矩阵`。

### 7.1 任务概览

新增：

- 目标主体数与扩展主体数
- 完成主体数
- 必查角色覆盖率
- 已发现、合理未发现、受限、待调查数量
- 强、较强、线索证据数量
- 查询可追溯性警示数量

覆盖率只作审阅提示，由确定性状态字段计算，不替代校验结果。

### 7.2 主体关系

新增关系路径用途和业务相关性列。未被任何人员身份或调查结果使用的扩展关系仍展示，但标为普通关系，不暗示其支撑人员纳入。

### 7.3 核心人员

新增：

- 证据直接记载主体
- 是否直接任职证据
- 关联路径

所属主体与目标调查主体分开显示，避免母公司层级被视觉隐藏。

### 7.4 证据记录

将来源列拆为来源类别、发布主体、原始位置，并增加`等级上限检查`。只有URL列创建超链接，显示文本仍保留完整可复制地址。

### 7.5 查询与缺口

拆分数据源名称、类型、实际访问位置、访问摘要、未命中范围和候选 URL。查询时间以 ISO 8601 文本写入，避免工作簿导入工具显示 Excel 序列值。

### 7.6 覆盖矩阵

每行一个目标主体，每列一个必查角色维度。单元格显示：

- 已发现：绿色
- 合理未发现：浅灰
- 访问受限或付费墙：黄色
- 待调查：红色
- 不适用：浅蓝，仅限允许的维度

每个状态附带查询或人员身份引用。矩阵冻结主体列和表头，支持筛选，不使用图表替代明细。

## 8. Skill 文档调整

`SKILL.md`保持入口简洁，只增加三个不可替代的核心约束：

1. 调查完成依据角色覆盖结论，不依据人员数量。
2. 人员归属以证据直接记载主体为准，跨主体纳入必须保存关系路径。
3. 搜索服务只发现候选来源，独立核验必须记录实际访问位置与内容。

详细字段、来源等级和完成门槛分别维护在`workflow.md`、`evidence-rules.md`和 Schema 中，避免重复。

## 9. 测试设计

所有实现遵循 RED-GREEN-REFACTOR。先以最小状态夹具复现当前校验器错误放行，再修改生产代码。

### 9.1 Schema 测试

- 缺失新增必填字段时失败。
- 枚举、URL/路径、日期时间和角色覆盖对象合法。
- 搜索服务候选 URL 可以为空数组，但不能作为证据原始来源。

### 9.2 业务校验测试

至少覆盖：

1. 泛化数据源被标为独立核验时失败。
2. 搜索服务查询被标为独立核验时失败。
3. 成功访问但没有访问摘要时失败。
4. 未发现但没有未命中范围时失败。
5. 未发现同时引用命中证据时失败。
6. 行业媒体标为较强或强证据时失败。
7. 母公司 CEO 直接挂到目标子公司时失败。
8. 关联主体人员缺少连续关系路径时失败。
9. 只有 CEO、其他角色待调查却标为调查完成时失败。
10. 每个必查维度形成合规结论时通过，即使部分结论是合理未发现。
11. 访问受限不会被误写为合理未发现。
12. 机构对象不能进入核心人员集合。

### 9.3 迁移测试

- 不修改输入文件。
- 输出存在时默认失败。
- 保留稳定编号和事实引用。
- 泛化旧查询降级为非独立核验并产生缺口。
- 无法分类的旧证据保守降级。
- 迁移后的状态通过 1.1.0 Schema，但不会虚假满足调查完成门槛。

### 9.4 渲染器测试

- 六张工作表名称和顺序正确。
- 概览统计与状态一致。
- 覆盖矩阵状态和引用正确。
- 人员表显示直接主体和关系路径。
- 查询时间单元格保存为 ISO 文本。
- 证据等级上限检查正确。
- 所有表头、冻结窗格、筛选器和状态色存在。

### 9.5 集成与视觉验证

- 从合规 1.1.0 JSON 校验并渲染 XLSX。
- 扫描公式错误和空白默认工作表。
- 渲染全部六张表，检查标题、表头、文本截断、状态色和覆盖矩阵。
- 使用历史 1.0.0 夹具执行迁移，在新路径生成 JSON 与 XLSX，不修改历史输入。

### 9.6 Skill 行为测试

使用独立、最小上下文的真实调查场景进行基线和更新后对比，重点观察：

- 是否仍用同一泛化模板填充多个维度。
- 是否把搜索摘要当成原始证据。
- 是否把母公司人员挂到目标子公司。
- 是否在只找到 CEO 时声称调查完成。

这些行为测试验证 Skill 指令是否有效；确定性脚本测试负责保证违规状态不能交付。

## 11. 实施顺序

1. 建立最小失败夹具，证明当前校验器会放行已知问题。
2. 升级 Schema 和初始化状态结构。
3. 实现迁移器并验证历史输入不被修改。
4. 加强查询、来源等级、主体路径和角色覆盖校验。
5. 更新状态派生逻辑和阶段判断。
6. 更新工作流、证据规则和 Skill 入口说明。
7. 更新 Excel 渲染器并新增覆盖矩阵。
8. 执行单元、集成、迁移、行为和视觉验证。
9. 更新版本号并完成发布前检查。

每一步以先失败、后通过的测试为完成条件；不得先改生产代码再补测试。

## 12. 验收标准

v1.2.0 只有在以下条件全部满足时才能发布：

- 泛化占位数据源不能通过独立核验校验。
- 搜索服务和用户材料不能作为独立核验证据。
- 来源等级不能超过类别上限。
- 母公司或关联主体人员不能错挂到目标主体。
- 只找到 CEO 时不能标记整个主体调查完成。
- 合理未发现必须可复现具体访问位置和未命中范围。
- Excel 明确展示每个主体的角色覆盖与缺口。
- 迁移不会覆盖或静默升级历史文件。
- 新增及既有自动化测试全部通过。
- 六张工作表完成渲染检查，无明显截断、错误状态或空白页。
- Plugin 版本在插件元数据、JSON 的`skill_version`和 Excel 的`Skill 版本`中一致；状态规范版本和渲染器版本分别与其各自声明一致。

## 13. 风险与控制

| 风险 | 控制 |
|---|---|
| 新 Schema 对历史状态不兼容 | 显式迁移器、只写新文件、版本检查 |
| 校验过严导致公开信息不足的主体无法完成 | 允许合理未发现、访问受限和付费墙，但要求过程可审计 |
| 来源类别映射存在判断空间 | 使用保守等级上限；不确定时归为其他/线索证据 |
| 关系路径建模增加录入成本 | 仅关联主体人员需要路径；目标主体直接人员不增加路径负担 |
| 覆盖矩阵鼓励机械填表 | 完成门槛同时要求具体查询记录和证据，不以矩阵状态单独通过 |
| 占位语黑名单误伤合法描述 | 只拦截有限的明确占位值，其他问题通过字段完整性和审阅警示处理 |
