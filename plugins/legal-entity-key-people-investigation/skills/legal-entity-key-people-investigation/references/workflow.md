# 调查工作流

## 输出位置

- 事实底稿：`working/legal-entity-key-people-investigation/state.json`
- 正式 JSON：`outputs/<项目或主体范围>_法律主体核心人员调查底稿_<YYYYMMDD>.json`
- 正式 Excel：`outputs/<项目或主体范围>_法律主体核心人员调查审阅件_<YYYYMMDD>.xlsx`

正式交付文件名遵循以下规则：

1. `<项目或主体范围>` 优先取 `任务元数据.项目名称`。没有项目名时，单主体取其规范法律
   名称，多主体按数量概括为 `二主体`、`十主体` 等。
2. `<YYYYMMDD>` 取 `任务元数据.调查基准日` 并去除连字符。
3. 清理 Windows 文件名禁止字符及末尾空格、句点。JSON 与 Excel 必须使用相同的范围名
   和日期。
4. 同一范围、同一调查基准日重新生成正式交付物时覆盖同名文件，不追加随机编号。
5. `state.json` 始终作为内部唯一事实底稿；正式 JSON 是通过校验后交付到 `outputs/` 的
   同一事实状态。
6. 正式 JSON 与正式 Excel 的状态数据必须保留同一个 `skill_version` 字段值，且该值应与
   当前 Skill 版本一致。

示例：`outputs/储能项目_法律主体核心人员调查审阅件_20260828.xlsx`。

状态校验通过后，运行 `python scripts/delivery_paths.py STATE_PATH` 确定两个正式交付路径；
脚本只输出路径，不复制或覆盖文件。

## 输入处理

自然语言、JSON 和 Excel 是等价入口。模型负责理解用户材料并规范化为内部状态；确定性
脚本从初始化或规范化后的 JSON 开始，不声称能够无歧义解析任意自然语言。

1. 冻结原始文件，不覆盖用户输入。
2. 登记文件或对话来源、类型、用途和可取得的 SHA-256。
3. 提取目标主体线索、产品或技术主题及用户明确给出的上下文。
4. 如用户提供客户项目名，保存到 `任务元数据.项目名称`；没有项目名时保留为空。
5. 为对象分配稳定编号并保存状态。
6. 检查启动门槛与关键主体歧义。

缺少主体或技术主题时停止。存在关键主体歧义时展示《调查任务确认单》并等待用户确认。

## 调查执行

按主体独立推进并在每次取得事实后保存：

1. 核验目标主体的规范法律名称和必要识别信息，记录`主体身份`查询。
2. 核验与人员调查有关的直接主体关系，记录`主体关系`查询并建立关系对象；没有关系结论时
   也保存实际查询结果。
3. 分别查询`控制与所有权`、`最高管理层`、`技术与研发负责人`；目标产品由明确业务线承载
   时再查询`目标业务负责人`。每个维度使用能够回答该问题的数据源和具体查询词。
   配置 `TAVILY_API_KEY` 时，可按[Tavily 检索说明](tavily-search.md)发现候选来源；每个
   Tavily 调用仍对应一个明确查询维度，不得用一条泛化查询替代各维度调查。
4. 每条查询记录`查询维度`和`是否独立核验`。调查人员实际访问原始官网、登记、监管文件、
   任命公告或其他原始来源时才标记为独立核验；仅阅读用户材料或其转述来源时标记为否。
   Tavily 返回的 URL、标题和摘要也标记为非独立核验；访问候选 URL 后另存原始证据和对应
   的独立核验查询。
5. 人员和人员身份分别建档；每段任职或身份单独记录，并区分目标主体、直接关联主体和
   二跳例外主体。
6. 证据只绑定其能够证明的主体、关系或身份。
7. 保存访问失败、付费墙、未命中和需人工补证的查询记录。不同维度不得合并为一条泛化的
   模板查询。
8. 计算各主体结果和整体状态。

单个主体阻塞不影响其他主体继续调查。

主体只有在以下条件全部满足时才能标记为`调查完成`：

- `主体身份`、`主体关系`、`控制与所有权`、`最高管理层`、`技术与研发负责人`均存在成功的
  独立核验查询，结果可以是已发现或已查询但未发现；
- 标记为`已核验`或`部分核验`时至少存在一条已核验人员身份；
- 标记为`未发现`时，控制与所有权、最高管理层、技术与研发负责人必须分别记录成功未命中；
- 调查进度不是`调查完成`时，事实核验状态不得为已核验、部分核验或未发现。

## 校验与审阅

1. 运行 JSON Schema 校验。
2. 运行跨对象业务规则校验。
3. 只有两项均通过才渲染 Excel。
4. 在对话中说明结论、限制和用户可执行动作，并提供审阅文件。
5. 等待用户明确确认、更正或补充。

用户更正必须先写回 JSON 及确认记录，再重新校验和渲染。不得直接修改 Excel 形成新的
机器事实，也不得自动进入专利检索或其他后续阶段。

## 版本说明

- `skill_version` 是正式 JSON、正式 Excel 与内部 `state.json` 的统一版本字段。
- 该字段记录当前 Skill 的语义化版本号，用于追溯交付物生成时所依据的 Skill 版本。
- 首次响应时应在消息顶部先输出 `Skill 版本：X.Y.Z`，再继续调查内容；其中实际版本号
  读取 `plugin.json` 的 `version` 字段。
- 同一调查任务的后续回复不重复输出版本行；只有用户询问版本或切换为新任务时才再次播报。
- Excel 的 `01-任务概览` 工作表中应显示标签 `Skill 版本`，其值取自 `skill_version` 字段。
